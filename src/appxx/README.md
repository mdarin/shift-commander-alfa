# Abstract layer (service/usecase)

Здесь реализуется верхнеурованевая прикладная логика уже на С++.

Данные вропперы можно использовать и как точки входа в Си код,
а непосредсвенно код с реализацией логики как-либо структурировать распределив по файлам.

В основном файле `src/freertos.c` с реализациями потоков исполнения задач FreeRTOS в цикле потока вызывается функция логики потока(или исполняемого кода пользователя, если так удобней мыслить).
Это точка входа для С++ кода из слоя абстрактнрой логики. Ниже данного увровня следует опусткаться только в случае необходимости использования новой перефирии.
Логика приложения не должна находится даже на уровне ОС. Это не догмат, но хорошая практика.

```cpp
void StartSomeTask(void *argument)
{
  /* USER CODE BEGIN StartShaftsMeasTask */
  uint16_t some_data_to_logic;
  /* Infinite loop */
  for (;;)
  {
    
    some_data_to_logic = fetch_data_from_source();

    appxx_execute_thread_some_logic(some_data_to_logic);

    osDelay(10);
  }
  /* USER CODE END StartShaftsMeasTask */
}
```

В каталоге `src/appxx/*.cpp` находятся реализации таких функций-точек входа `appxx_execute_thread_some_logic(uint16_t data)`.
Вероятно следует такие функции отмечать префиксом `appxx_<func-name>`.

```cpp
#include <stdint.h>
//...

// Здесь можно уже объявлять С++ объекты глобальные

extern "C"
{
    void appxx_execute_thread_some_logic(uint16_t data)
    {  
        // Здесь используется С++ код для реализации прикладной логики
    }
}
```

Данная функция `appxx_execute_thread_some_logic` по сути является представлением ресурсов процесса операционной ситемы в рамках которого поизводится исполнение пользовательского кода.

В `main.c` желательно ограничиться только инициализациями перефирии и создаваемых глобавльных объектов в памяти на уровне всего приложения(буферы, флаги и пр.).
Остальное лучше по максимуму уносить на слой абстрактной логики.
